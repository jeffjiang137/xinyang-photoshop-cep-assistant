常见问题

先按这里排查，再导出调试报告。

插件没有显示

确认安装路径和 manifest.xml，并在“首选项 → 增效工具”勾选载入扩展面板。

覆盖后还是旧版本

设置页点击“重新加载插件”；仍无效时退出 Photoshop 后重新安装。

多选文字属性变慢

使用 v2.1.71 之后的增量批量更新，避免宿主任务同时排队。

OCR 颜色或分组不准

尽量框选纯文字区域，减少高光线、投影和图标干扰。

LaMa 无法使用

检查 8867 或 IOPaint 服务；不可用时改用 PS 内容识别填充。

鑫洋助理 v2.2.04 更新说明

本次重点：优化“横向拉伸 / 纵向拉伸”擦除算法，减少文字残影、脏边和长条拖影。

1. 采样不再紧贴文字边缘，新增安全距离（guard band），优先从文字附近但避开边缘污染的位置取样。
2. 同一方向会扫描多组近邻候选像素带，并优先选择不与其他待擦除文字范围重叠的候选。
3. 横向拉伸使用更宽的竖向采样带；纵向拉伸使用更宽的横向采样带，降低单个脏像素被无限放大的概率。
4. 采样带先沿拉伸方向压缩为 2px 的“纹理剖面”，使用双三次插值平均零散抗锯齿、细小文字残留和噪点，再拉伸覆盖擦除区域。
5. 保留与拉伸方向垂直的背景渐变和明暗变化，比直接复制 1~16px 边缘条带更自然。
6. 附近候选无法复制时自动继续向外扫描；最后仍保留兼容回退，不会因局部透明区域直接失败。
7. v2.2.03 的负间距、v2.2.02 的嵌入下方图层、v2.2.01 的诊断优化全部保留。

建议：横向文字优先尝试“横向拉伸”，竖向文字或横向纹理明显的背景可尝试“纵向拉伸”；复杂纹理仍优先使用 LaMa / PS 内容识别填充。

OCR 规则与限制
--------------
· 本机服务检测地址固定为 http://127.0.0.1:8866，可在设置页重新检测。
· 本机服务可用时优先调用；不可用时自动使用已保存的 OCR API。
· 本机 POST /ocr 使用 multipart/form-data，请求图片字段名为 image。
· OCR API 使用 JSON 请求，字段为 image_base64、filename、group；需返回文字内容和坐标框。
· 安装包不包含 OCR 模型、本地服务、Python 依赖和服务启动脚本。
· 每个识别结果生成独立可编辑文字图层，不再为每行创建子组。
· 图标与文字穿插时，插件会从 OCR 宽框中剔除图标和竖线占位；OCR 返回整条超宽框时，再按连续文字像素区拆成独立短语。
· “115名”“20台”“99%”等数字与较小单位会拆成不同字号的独立文字图层。
· 阿拉伯数字优先使用 Arial；粗体数字优先使用 Arial Bold。
· 黑体优先使用 Source Han Sans SC（思源黑体），宋体优先使用 Source Han Serif SC（思源宋体）。
· 如果本机未安装思源字体，会依次回退 Noto CJK、微软雅黑/黑体或宋体。
· 颜色、字重、字号、旋转角度和位置属于图像估算值，复杂艺术字、描边、投影和变形文字需要人工微调。
· 文字横向、纵向缩放固定为 100%，不通过拉伸压缩贴框；中文 tracking 限制为 -80 至 120，拉丁字母/数字限制为 -60 至 120，混排限制为 -70 至 140。
· 生成文字通过字号与字间距拟合覆盖原文字；擦除时需单选或多选可编辑文字图层，只清理这些图层下方对应的底图文字像素。
· LaMa 支持旧版 8867 自定义服务和 IOPaint 8080，也可在设置页填写自定义地址。
· 插件会按需检测 /health、/inpaint/health 或 IOPaint /api/v1/model，并根据服务类型调用对应修复接口。
· 模型不随 CEP 内置；可在设置页点击“启动 IOPaint”运行随包脚本，首次启动需要联网安装依赖和下载模型。
· LaMa 不可用时不会自动冒充成功，请改用横向拉伸、纵向拉伸或 PS 内容识别填充。
· 所有擦除方式只新增局部修复图层，不覆盖原图片；选择不同文字时修复结果可累积，对同一批文字切换方式时会隐藏该批文字的上一修复层。

· 自动匹配：以前 5 张成功读取的原图宽度中位数为依据，选择更接近的画布宽度

· 宽度区域：只显示画布宽度、790 和 1920，不再显示按钮右侧状态说明
· 缩放方式：每张图片等比例缩放到当前选中的画布宽度
· 排列方向：从上到下
· 初始图片间距：0px
· 图层结构：每张图片一个独立嵌入式智能对象图层
· 图层名称：两位顺序号 + 原文件名
· 原文件：只读取，不修改

间距规则
--------
· 左右边距为正数：当前图片等比缩小，两侧各增加对应数值的边距。
· 左右边距为负数：当前图片等比放大，两侧各超出对应数值的距离。
· 上间距、下间距：只允许大于或等于 0 的整数。
· 标题拖拽：向右拖动增加数值，向左拖动减少数值，每移动 1px 调整 1px。
· 一键清零：只重置三个输入框，不会立即修改 Photoshop 文档。
· 每次确认后：自动重新排列全部图片，并更新画布高度。
· 间距区域：保持透明，不创建额外填充图层。
· Photoshop 历史记录：一次间距调整合并为一个步骤。
· 智能对象：缩放与重排不会栅格化图层，可继续无损调整。

一、生命周期与闪烁根因
----------------------
发现的主要问题：
1. 持久化请求发生在业务脚本加载后，CEP 页面在 Photoshop 切换面板时存在先被释放再重建的窗口。
2. 导航切换曾通过根节点属性驱动全局 CSS 重新匹配，大型文字/工具面板会出现明显重排。
3. 返回面板时部分模块会读取 Photoshop 属性、检测服务或写入配置，和 CEF 首帧绘制争抢主线程。
4. GuideGuide bridge 的开发模式保留 iframe onload -> location.reload，虽然通常只在开发扩展 ID 下触发，但属于可导致整页销毁的风险。

处理结果：
- 在 head 内联引导阶段先读取后台设置并发送 Persistent 事件。
- runtime 再进行一次正式持久化请求和短延迟重试。
- 隐藏/恢复只分发轻量生命周期事件，不重建 DOM、不重新拉取数据。
- 页面切换只关闭前一页、打开目标页；不再修改运行期根节点选择器。
- 按页面保留滚动位置，表单和抽屉依赖原 DOM 自然保留。
- GuideGuide iframe 使用 lazy src，首次进入才加载，之后不改 src。
- 移除所有实际 location.reload 调用。

结论：开启“后台运行”且 Photoshop 接受 Persistent 事件时，插件自身不会在切换回来时重载。关闭后台运行时，宿主可以释放页面，这是用户设置对应的正常行为。
